# Pixora 0.9.0 / code 19: UX and offline Recreate verification

This change follows the owner's approved 24 October 2026 plan on `codex/expo-kinetik-recreate`, targeting the existing draft PR into `release/0.9.0`. It preserves the package, signing identity, enhancement weights, imported images, previous results and saved settings. It is not a main merge, public release or store submission.

## Implemented behavior

- Native launch, the first React frame and system panels target the selected light/dark background. A candidate recording exposed a transient light palette under an explicit dark preference. Startup now waits for settings hydration before releasing the native frame, and applies the first resolved palette without interpolation; later user theme changes keep the transition. Cold-launch recordings of the final candidate confirm the light/dark transition without the rejected opposite-palette frames. Aurora and the logo fade in from it; there is no text wordmark. The minimum is 1500 ms of foreground-visible splash time, followed by any remaining required initialization.
- Three passive onboarding scenes use horizontal paging: bridge detail, a drawn mountain landscape and private on-device processing. Completing or skipping persists once; an unsuccessful write can be retried. Settings replay returns to Settings. Reduced motion and inactive/background pages stop animation.
- Both modes open a separate model screen. Selection returns immediately; expanding the description/comparison is independent. Enhance retains eight presets; Recreate presents the actual optional SD 1.5 + LCM model. Downloads start in place. The main action is Recreate in that mode.
- Dialog actions stack and wrap. Licenses is a text link. Focused input fields are scrolled above the keyboard; Android also adjusts the containing height. Processing shows the image scan, a status pill, elapsed time and cancellation, without Aurora, duplicate bars or a tiled-processing explanation. A fresh success opens comparison directly with one confetti effect and no Aperture Card.
- Downloading uses a foreground data-sync service, byte progress, cancellation, resumable temporary files and SHA-256 verification. Duplicate starts are reserved atomically. Cancellation also interrupts large-file hashing, and an active verification phase cannot be reported ready prematurely. Notification refusal does not block transfer. Cache cleanup keeps installed weights.
- Storage categories are disjoint; Android path aliases resolve consistently. Presentation uses decimal MB/GB, including free space and individual category values, while existing binary cache-limit values retain their byte sizes. The slider has a thumb and positions, with one heading.
- A new successful result may show a star dialog once per five minutes. The per-result decision survives restart. A completed 1–4-star gesture opens Feedback with the rating; 5 opens the fixed Play listing. No confirmation button, review publication or automatic support submission is added. Screen-reader users can adjust then activate.
- Analytics retains technical job/model/recommendation/dimension/format/alpha/duration/error context and the compact-profile tag. Download start/finish share one attempt token, pinned model revision and real downloaded/total/installed byte counts; finish also records monotonic duration and status. Tests reject duplicate late completion callbacks. Events reject more than 25 accepted fields. Consent remains independent of Remote Config. Images, paths, filenames, EXIF, prompt text and support content remain excluded.

The owner explicitly retained selective Play routing after discussing its policy risk. This implementation is not evidence of Google Play policy compliance.

## Recreate profile selection

The optional two-file package is unchanged at 1,881,812,340 bytes, with pinned revisions, licenses and SHA-256 values. Inference remains CPU-only and offline. SDK contexts use disk-backed weights, mmap, disabled prefetch/eager loading and no conditioning cache. A managed SDK budget is not an OS RSS limit. Inspection of the pinned SDK found that CPU capacity enforcement is bypassed and CPU graph segmentation is disabled; changing this value is not a proven CPU-memory or speed optimization. The measured candidate also requires 2 GiB of OS-available memory before launch; this is separate from the SDK budget.

The initial 256-pixel diffusion canvas produced severe false color on the fixed mountain input on both host and Xiaomi. Changing the budget between 512, 768 and 1024 MiB gave identical bad pixels; those outputs are rejected, despite successful execution and saved PNGs. Small VAE tiles also caused visible bands in host comparisons.

The selected candidate instead resamples content into a 512×512 diffusion canvas with reflected padding and disables VAE tiling. It crops the generated region and resamples to the retained public long-side cap of 256 px, before the existing real AI upscaler produces the displayed 2×/4× size. Both 4- and 8-step host examples had coherent colors without the rejected edge band; 8 steps changed the scene more. A further 384-square host candidate showed grid/stripe artifacts and was also rejected. Even the 512-square output can change mountain ridges into wave-like forms. Color coherence is not scene fidelity: this is limited image-level calibration, not a general quality guarantee. Alpha is restored by the caller, and diffusion resources are released before ncnn starts.

JNI now cancels on Java callback/worker-attach failure and validates pixel count and RGBA stride before allocating the packed image. Diffusion input composites premultiplied source colors over white, leaving opaque pixels unchanged and preserving exact output alpha; this avoids conditioning transparent regions on black. Host tests check the matte, alpha restoration, padded rows, cancellation and resource ownership.

Independent read-only reviews checked the JS navigation/rating/keyboard paths and Android download/storage/privacy/native boundary. A proposed delete/start race was rejected after verifying that both complete bridge calls use the same serial executor; no extra lock was added. Explicit cache clearing can invalidate a temporary share file already being read by another app, a retained cache-lifecycle limitation.

The strict whole-app coverage gate remains failed; current iOS owned files are also absent from the full coverage denominator. Existing unresolved dependency-security findings remain open. No threshold, source inclusion rule or failure history was weakened to obtain a pass.

The signed b37 artifact includes the first-tap keyboard correction on the Settings scroll container, Android locale/layout-direction configuration handling, independent system-locale lookup and nested `ENOSPC`/`EDQUOT` download-error mapping to `LOW_STORAGE`. Xiaomi checks confirmed Arabic selection and return to system English in place without restarting. The ordinary button label also wraps at large font sizes. Cold-launch recordings in both themes, large-font/reduced-motion onboarding replay and fresh-onboarding Finish/Skip, separate closed-model selection, both focused input fields above the keyboard, cache clearing with the result and 1,881,812,340-byte model retained, in-place download cancel/resume after force-stop and partial-package deletion passed on this exact artifact. A real Lite Enhance result completed in four seconds at 512×228. Four stars opened Feedback with 4/5; a restored result and a new result inside the five-minute interval did not prompt again. After the interval, five stars opened Google Play only on release. No review or test email was submitted. These are bounded physical checks, not whole-platform acceptance.

The final signed APK is `0.9.0/code 19`, ARM64, SHA-256 `fa0846e039f336c9b17247ce6c7d0804709ada6e6130a36f0af1ff04526225b6`, 250,358,630 bytes. Its signing certificate, package/version, 16 KiB ZIP/ELF alignment, all ten bundled model checksums and absence of private keys or optional download weights were verified. The installed base APK hash matches. It is copied to Downloads; the final Recreate matrix and source push are still in progress.

The eight-step TIME_LIMIT is retained as a failed functional run; extending the Recreate product deadline does not turn it into a pass. The final build must produce an actual saved eight-step result and a fresh three-job sequence.

A deliberate UI cancellation of an early full-service run reached CANCELLED without a saved result or crash; the test restored its staged session. Its success assertion correctly failed, because the run was cancelled. This run is cancellation evidence, not one of the required successful generations.
