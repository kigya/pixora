# План 0.8.0 и release handoff

Статус: реализация утверждённого объёма 0.8.0 интегрируется; финальная проверка и release handoff pending. Этот roadmap фиксирует только уже одобренные требования из [основного PRD](../PRD.md), [workflow PRD](prd.md) и [решений](../engineering/decisions.md). Он не утверждает дополнительные возможности, сроки или коммерческие планы.

## Утверждённый объём 0.8.0

1. Сохранить текущий offline Android сценарий и добавить локальную эвристическую рекомендацию режима, которую пользователь может принять или проигнорировать; пояснить подготовку больших исходников с фактическими размерами и неизменностью оригинала. Эффективность рекомендации остаётся гипотезой, не результатом рынка.
2. Завершить существующий iOS порт основной цепочки с ncnn CPU inference, экспортом, отменой и явно ограниченным поведением при уходе приложения в фон.
3. До сбора показать новое пояснение и получить отдельные добровольные выборы Analytics и Crashlytics; старый флаг показа уведомления не считается согласием. Remote Config остаётся отдельным сервисом. После успешного экспорта показывать нейтральный системный review prompt без фильтрации по звёздам.
4. Первично спросить язык на свежей установке, синхронизировать системную локаль на обеих платформах, сохранить выбор и данные существующей установки при обновлении, поддерживать новые утверждённые локали и миграцию `pt` в `pt-BR`.
5. Сохранить обратную связь как отдельное, явно отправляемое действие с необязательным email для ответа, ограничениями размера/rate/idempotency и информацией о платформе/версии. Не включать форму поддержки в Analytics.
6. Оставить Android minification/R8 и resource shrinking отключёнными, завершить утверждённые локальные quality gates и собрать проверяемый release handoff. Интеграция/CI/Git выполняются root по ADR-806.

Точные требования и TEST-ID находятся в таблице [FEAT-801–806](prd.md). Не расширять объём новыми моделями, облачной классификацией, аккаунтами, рекламой, paywall или monetization.

## Порядок завершения и критерии handoff

1. Закрыть интеграционные source/test/documentation blockers и сохранить строгие тестовые пороги. Наличие тестов без зелёного результата не считается завершением.
2. Получить нативные проверки Android, C++ и iOS для соответствующих TEST-ID; не подменять native/device checks JS тестами.
3. Пройти отдельные физические gates debug и release на Samsung SM-S916B по [device report](../quality/device-report.md), с реальным локальным inference/export и точными артефактами. Текущая установка debug сама по себе не является PASS.
4. Проверить согласие/default-off/upgrade/revoke, независимость Remote Config, системный review prompt, обратную связь, языки/RTL/large text и платформенные фоновые ограничения. Сетевую доставку Firebase или письма отмечать только при наличии соответствующей записи проверки.
5. Подготовить локальный release handoff: version/code, target configuration, hashes, тестовые отчёты, ограничения и оставшиеся неизвестные. Definition of Done и фактический результат сверяются с root quality/status документами.

Этот workflow завершается release handoff. Signing для магазина, GitHub Release, публикация в Google Play/App Store и submission не входят в этот этап.

## После 0.8.0

30/60/90-дневный план, привлечение пользователей, монетизация и цены не утверждены и не добавляются этим документом. Сначала нужно завершить 0.8 acceptance и, при отдельном решении владельца, сформулировать следующую проверяемую продуктовую гипотезу. Технические показатели из [метрик](metrics.md) описывают использование и надёжность; они не предсказывают спрос или выручку.
