# Feature registry 0.8.0

Authority: [workflow PRD](prd.md), [primary PRD](../PRD.md) and explicit ADR-801–814 decisions. Requirement sources and hypothesis boundaries remain in the PRD; research does not automatically add features.

- FEAT-801 — implemented. Local post-import suggestion, manual Apply, hiding for the current photo and preservation of manual mode/scale. JS/native boundary checks PASS; Samsung debug JNI/Maestro and owner review apply to the source states recorded in local device evidence. Recommendation usefulness remains a heuristic hypothesis without a representative labeled quality sample.
- FEAT-802 — implemented. Working/original/output dimensions and explanation of memory, time, possible detail loss and original preservation; 1024 px long-edge limit and separate Fast 512 limit. Unit/native checks and the recorded Samsung debug scenario PASS. An updated physical matrix is deferred.
- FEAT-803 — implemented. Offline iOS CPU ncnn/shared engine, all 8 presets/5 models, codecs, seams, bounded background execution, cancellation and recovery. Current simulator XCTest: 52/52, 607/607 lines and 794/794 branches; generic-device Release evidence is held locally. This is not physical iPhone or Store acceptance.
- FEAT-804 — implemented. Default-ON notice under the latest explicit owner decision, independent saved opt-outs and responsive serialized switches; neutral review requests, optional feedback email/platform. JS/Kotlin/iOS/backend tests PASS. Exactly 2 separately authorized emails were delivered with verified Reply-To; Android Analytics/JVM+NDK QA reports were confirmed. The full Firebase matrix and iOS ingestion are incomplete.
- FEAT-805 — implemented. 34 active locales plus Portuguese compatibility, native sync, initial selection, RTL registry and consistent Feedback/Privacy/Licenses headers. Schema/placeholder/flag-hash and automatic locale/layout tests PASS; the physical Urdu/Hebrew/settings journey is recorded locally. Native-speaker review and a full physical locale matrix are unavailable.
- FEAT-806 — workflow implemented. Task PRs → release/0.8.0 → one final squash [PR13](https://github.com/kigya/pixora/pull/13) into main. CI runs only on main pushes; see [GitHub Actions](https://github.com/kigya/pixora/actions/workflows/main.yml). Exact SHA/receipt records stay local. Strict owned-language coverage, source presence, security and Android/iOS release builds are required; production signing, stores and GitHub Releases use a separate workflow.

TEST-807 covers manual-review clarifications and splash max(loading, 1500 ms), the iOS attachment clock, Android readiness/deadline and cleanup. Shared navigation/splash lessons are stored only in the private local database. ADR-814 permits automatic checks and fixes without a new Samsung installation/UI check. Unit/build PASS never substitutes for physical PASS; release readiness remains bounded by explicitly deferred gates.
