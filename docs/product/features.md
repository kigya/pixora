# Feature registry 0.8.x

Authority: [workflow PRD](prd.md), [primary PRD](../PRD.md) and explicit ADR-801–817 decisions. Requirement sources and hypothesis boundaries remain in the PRD; research does not automatically add features.

- FEAT-801 — revised locally on 2026-10-17. Shared native multi-scale/patch policy recommends Standard/Natural/Balanced/Art/Pixel with phase-aware two-axis grid detection, alpha handling and a common availability fallback; Lite is manual or fallback. Manual Apply, hide-after-Apply and scale preservation remain. New reasons are translated in all 34 active locales and the compatibility Portuguese dictionary. Native/JNI/Kotlin/iOS/component scenarios were updated but NOT RUN at owner request. The signed Android release built and was installed over USB; the owner accepted it and authorized publication as 0.8.5/code 15. The metadata-only version bump has not been rebuilt. Accuracy, size and latency remain unmeasured; historical Samsung/coverage evidence does not verify this revision.
- FEAT-802 — implemented. Working/original/output dimensions and explanation of memory, time, possible detail loss and original preservation; 1024 px long-edge limit and separate Fast 512 limit. Unit/native checks and the recorded Samsung debug scenario PASS. An updated physical matrix is deferred.
- FEAT-803 — implemented. Offline iOS CPU ncnn/shared engine, all 8 presets/5 models, codecs, seams, bounded background execution, cancellation and recovery. Local 0.8.3 simulator XCTest passes 52/52 with 607/607 lines and 794/794 branches; its unsigned generic-device Release also passed with explicit XcodeDefault selection. Actual 0.8.2 main CI iOS linking failed (ADR-817); the corrective version still requires its own successful main run. This is not physical iPhone or Store acceptance.
- FEAT-804 — implemented. Default-ON notice under the latest explicit owner decision, independent saved opt-outs and responsive serialized switches; neutral review requests, optional feedback email/platform. JS/Kotlin/iOS/backend tests PASS. Exactly 2 separately authorized emails were delivered with verified Reply-To; Android Analytics/JVM+NDK QA reports were confirmed. The full Firebase matrix and iOS ingestion are incomplete.
- FEAT-805 — 0.8.4 changes first launch to Home with the system language; manual choice remains in Settings. The dedicated language onboarding route is removed (ADR-818; LESSON-0006). The existing 34 locales, Portuguese compatibility, native sync, RTL registry and consistent Feedback/Privacy/Licenses headers remain. Earlier schema/placeholder/flag-hash and locale/layout results belong to 0.8.3; the owner requested no new checks for this change. Native-speaker review and a full physical locale matrix remain unavailable.
- FEAT-806 — workflow implemented. Task PRs target `release/<version>`, followed by one final squash into main. The initial 0.8.0 squash is [PR13](https://github.com/kigya/pixora/pull/13); subsequent corrective versions retain their failed-run history under ADR-815–817. CI runs only on main pushes; see [GitHub Actions](https://github.com/kigya/pixora/actions/workflows/main.yml). Exact SHA/receipt records stay local. Strict owned-language coverage, source presence, security and Android/iOS release builds are required; production signing, stores and GitHub Releases use a separate workflow.

TEST-807 covers manual-review clarifications and splash max(loading, 1500 ms), the iOS attachment clock, Android readiness/deadline and cleanup. Shared navigation/splash lessons are stored only in the private local database. ADR-814 permits automatic checks and fixes without a new Samsung installation/UI check. Unit/build PASS never substitutes for physical PASS; release readiness remains bounded by explicitly deferred gates.

- FEAT-807 — implemented for0.8.6: fixed full-policy URL button with localized label/error in34 active locales plus legacy Portuguese; existing summary retained. Privacy website updated against Android/iOS source and observed Analytics settings. TEST-808 scenarios are documented but NOT RUN under explicit build-only scope. Build/publication evidence is recorded separately and does not establish runtime acceptance.
